# Sigil Site Redesign Research

## Working thesis

Sigil should look like the machine it sells: an exact, editable specification
becoming a complete interface. The strongest territory is editorial technical
publishing crossed with an industrial foundry, using liquid metal only as a
selective signal of transformation.

The product proof must appear in the first viewport. The page should make the
causal chain visible:

`DESIGN.md -> 519 tokens -> CSS + Tailwind v4 + W3C JSON -> 350+ components`

## Principles mined from the wiki and bookmarks

1. Show the mechanism before making the claim.
2. Use off-black and off-white as semantic tokens. Metal is a focal material,
   not a wallpaper.
3. Let typography, structural rules, and negative space carry most of the page.
4. Use GSAP for a real narrative sequence. Use Lenis only where scroll phase
   must stay synchronized with that sequence.
5. Build breadth first, then deepen the strongest directions.
6. A fresh critic sees the rendered page, not the builder's reasoning.
7. Fix one largest visual gap per loop to preserve causal clarity.
8. Compare desktop, mobile, light, dark, reduced motion, and interaction states.

## Anti-patterns

- Centered generic hero with blur blobs
- Pill navigation, three equal feature cards, or bento soup
- Purple-on-black "AI" styling
- Metal, glass, and glow applied to every surface
- Decorative diagrams that do not explain the token pipeline
- Fake controls or empty interaction affordances
- Scroll hijacking without a narrative reason
- Oversized copy that displaces product proof below the fold

## Evaluation model

Each concept is scored on product legibility, distinctiveness, typography,
composition, material restraint, interaction quality, responsive behavior,
theme fidelity, accessibility, and performance. A concept does not pass because
its author likes it. It passes when a fresh reviewer can identify what Sigil is,
how it works, and why the visual system belongs to the product.
